# grok45-final-review-gates - Work Plan

## TL;DR (For humans)

**What you'll get:** Atlas's final review wave stops trusting checkbox text and starts demanding proof: every final-review task in a plan declares WHICH specialist must run it, the system checks that the real specialist actually ran and approved, and that proof survives restarts and compaction. On your Grok setup this kills the observed failure where Grok Atlas quietly reviewed its own work with another Grok worker instead of real reviewers.

**Why this approach:** Plans get a small machine-readable role tag on each final-review line (works in both OpenCode and Codex), and OpenCode enforces it with durable receipt files instead of in-memory counters — because the investigation proved the only trustworthy identity is the one the harness itself resolves, and anything kept only in memory can be wiped by compaction or bypassed by editing a checkbox. Legacy plans without tags keep working exactly as before; nothing can brick mid-upgrade.

**What it will NOT do:** It does not change how ordinary Grok implementation work is delegated (categories still route to the Grok worker). It does not add real enforcement on the Codex side — Codex gets the new plan syntax and guidance only. It does not create a new Grok-specific Atlas prompt.

**Effort:** XL
**Risk:** Medium - the enforcement gate touches live session orchestration; mitigated by advisory-first rollout, fixtures proving both failure and success paths, and graceful degradation for old plans.
**Decisions to sanity-check:** reviewer mapping F1=plan auditor/F2=code quality/F4=scope fidelity → momus/oracle/momus; a brand-new `qa-executor` subagent for real manual QA (F3, writes only evidence files); durable receipts as JSON sidecars next to plans with the wave baseline stamped once at start; Codex parity limited to syntax + prompt guidance; `default.md` keeps the `pass-final-wave` umbrella todo (the compaction preserver depends on it) instead of dropping it.

Your next move: start work, or run a high-accuracy dual review of this plan first. Full execution detail follows below.
